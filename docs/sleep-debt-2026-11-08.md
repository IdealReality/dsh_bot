# 「大肥鱼一直很累」——睡眠债模型的定标错误（2026-11-08）

用户观察：「大肥鱼似乎一直表达的都非常累。」

不是模型爱抱怨，也不用人格提示词去压。**她的身体读数里，"缺觉"是常态**，
每一轮 system prompt 都带着那一行，模型只是照着念。

---

## 一、直接证据（不是推断）

生产的 system prompt（容器内直接调 `assemble.assemble()`，只读）：

```
身体：感觉缺觉，脑子发钝。
心里：我说不上好也说不上坏。
```

同时 `field.json`：`sleepDebt = 0.687`（`sense()` 的阈值是 0.45），
`fatigue = 0.174`（阈值 0.30）、`cortisol = 0.162`（阈值 0.50）—— 只有睡眠债过线。

## 二、根因：累积速率与还债速率不匹配，债被永久钉在阈值之上

| 环节 | 事实（代码里读出来的） |
|---|---|
| 清醒累积 | `organ/heartbeat.accrueSleepDebt`：白天 0.02/h，深夜 23~6 点 0.05/h |
| 一天的量 | 典型 17h 醒 + 7h 深夜 = 0.34 + 0.35 = **0.69** |
| 一次真睡最多 | `sleepstage`：480min × 0.855 效率 = **effectiveH 6.84h** |
| 旧还债 | `field.repaySleep`：`debt *= exp(-h / 9.4)` → 一夜只清 **48%** |
| 上限 | `sleepDebt` 上限 1.0 |

算式的不动点：每天欠 0.69、每晚最多清掉当前值的一半
→ **醒来 0.48 / 睡前 1.0**，而 `sense()` 的「缺觉，脑子发钝」阈值是 0.45。
也就是说，**她每天一睁眼就已经"缺觉"**。

实测吻合：2026-11-08 07:48 醒，反推睡前值 = 0.443 / exp(-6.84/9.4) = **0.916**（顶格），
到 19:57 累到 0.687。

用真实睡眠时刻表（`sleep.json.history`）做 8 周期仿真：

| 还债 half-life | 清醒时段里「缺觉，脑子发钝」占比 | 平均债务 |
|---|---|---|
| 9.4h（旧） | **86.9%** | 0.650 |
| 6.0h | 48.5% | 0.461 |
| 4.5h | 32.9% | 0.378 |
| 3.2h（新） | **24%** | 0.32 |

剩下那 24% 是真实熬了 20h+ 的长段 —— 那本来就该困，不能一起抹平。

## 三、修法

1. `tools/brain/field.mjs`：`repaySleep` 的时间常数提成具名常量并定标
   `SLEEP_REPAIR_TAU_H = 3.2`（一夜清 ~88%，醒来 0.08~0.12）、`FATIGUE_REPAIR_TAU_H = 5.5`（原值）。
   取值同时满足三条：正常白天不到"缺觉"、连熬 20h 以上仍判得出困、
   连熬 24h 才够到"来不及睡"的兜底线。
2. **必须同时改掉入睡门槛**（否则她会从"一直很累"变成"再也不睡"）：
   实测她历史 6 次真入睡的 `why` **全部**是 `欠觉欠到撑不住了（30~36/100）`，
   也就是只靠 `debt >= 0.92` 这条硬底进的睡（"积压"从没到过 66）。
   0.92 之所以天天踩得到，正是因为还债定标错了。定标修好后债不再顶格，
   所以 `organ/night.mjs` 新增 `RULES.debtSleepAt = 0.7`：
   按新曲线那对应"熬到深夜 4~5 点、约 20~21 小时没睡"，是真该睡的点；
   0.92 保留为"来不及睡"的兜底（`debtCollapseAt`）。
3. 一次性状态校正：现存 `sleepDebt` 是"旧模型下被顶格"的值，按新模型重算
   （1.0 × exp(-6.84/3.2) + 醒后 12.28h 累积 = 0.364），备份 `field.json.bak-20261108-debtfix`。

## 四、顺带查出来的第二个静默 bug：`spinalState()` 会写盘

`tools/brain/spinal.mjs` 里把它当谓词用：

```js
try { asleepNow = asleep(now) === true } catch { ... }   // asleep 来自 rhythm.mjs
```

`rhythm.asleep()` 是**记一次入睡的写操作**（`return save(st)`，永远不是 `true`）。后果：

- 每读一次表达读数就往 `rhythm.json` 追加一条假 `sleep` 并把 `lastSleep` 重置成 now
  —— 实测 30 条 history 里 **29 条是假的**，`lastSleep` 比 `lastWake` 还晚；
  真醒来时 `awake()` 算出"睡了 0.01 小时"。
- `=== true` 恒为 false，"半梦半醒"这条表达档从来没触发过。

修法：改读 `sleepstage.snapshot(now).inSleep`（纯读）；数据用 `sleep.json.history` 重建
（备份 `rhythm.json.bak-20261108-spinalfix`）。

## 五、第三个同类 bug：代谢电量永远贴着 0（"饿得发慌"每轮都进 system）

修完睡眠债之后，`field.sense()` 变成「感觉有点欠觉；**脑子转不动了，饿得发慌**。」
后者来自 `organ/metabolism.mjs`：`energy` 实测为 **0**（`stats.messages 615 / binges 0`）。

实测（沙箱，真实 sleepstage 分期）：16h 清醒 + 600 条消息 → energy 从 0.05 掉到 **0**；
再睡足 8h → 只回到 **0.272**。也就是"一天花 0.28、一夜补 0.27"——
收支贴在 0 上，而 energy 在 0 处截断，于是她**永远见底**，每轮都在说"饿得发慌"。

修法：睡眠从"按分钟加固定量"改成**朝满电饱和恢复**（`SLEEP_FULL 0.9`、`SLEEP_TAU_MIN 200`，
阶段权重 N1 0.35 / N2 0.8 / N3 1.6 / REM 1.0）。修后沙箱 3 天稳态：
傍晚 0.62 / 醒来 0.87，`sense()` 为空；一夜从 0.02 回到 **0.815**。
live 校正：`energy 0 → 0.75`（新口径下此刻该在的位置），备份随 `recalibrate` 落 `recalibrated` 标记。

## 六、验证

新增 `test/brain-sleep-debt-test.mjs`（已注册进 `tools/run-tests.mjs`），**16 项全绿**；
换回旧实现会红 8 项（睡眠债）/ 2 项（spinal 写盘）/ 2 项（代谢回充），回归方向是钉死的：

```
① 一夜 6.84h 后：起点 0.5 → 0.059 / 0.92 → 0.109 / 1.0 → 0.118   （旧：0.242 / 0.444 / 0.483）
② 稳态 5 轮：每轮醒来 ≤0.15，14h 正常白天 0.380 < 0.45
③ 连熬 20h → 0.650（仍判得出困）+ sense() 说缺觉
④ 睡醒后 sense() = 「感觉身上没什么乏的，还算清爽。」（旧：「感觉缺觉，脑子发钝。」）
⑤ spinalState 连调 3 次，rhythm.json 一个字节不变；真睡着时报「半梦半醒」
⑥ debt=0.7 单独判定该睡（score=25），debt=0.44 不触发（score=16）
⑦ 见底时 sense 说「饿得发慌」；一夜 8h → energy 0.815，醒来 sense 为空
```

生产生效：`bot.mjs qq-server` 重启（PID 227710 → 228190），心跳/装配/结算全在新代码上；
活数据复核 `sleepDebt = 0.364` → system 里那一行变成「身体：感觉有点欠觉。」
（12.3 小时没睡，本来就该"有点"，不该是"缺觉"）。全套 `node tools/run-tests.mjs` 114 套通过。

> 注意：`repaySleep` 只在 `sleepstage.wake()` 里跑，所以**新常量要等下一次真睡才体现**：
