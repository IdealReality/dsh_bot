# 专题研究器官（research）· 十遍循环（2026-11-07）

> 用户原话：「我想在 QQ 里叫她去 B站专门看一类视频，她似乎并不能很好的将思维递归下去，
> 从 化学/生物学/哲学/主观/精神学/心理学 这几个方面去研究与提升
> 然后需要进行十次的 全链检查→高压测试→修缮→优化与增强功能→维护一遍 的循环」

## 一、先说病根（不是模型不行）

实测取证（容器内真实链路）：

| 观察 | 证据 |
|---|---|
| 她能"看一条视频" | `debrief` 四路材料（字幕/台词/热评/画面）+ `watchlog` 记账 |
| 她也"能答应" | 工具链里有 `watch_video(bvid)`，聊天里能调用 |
| 但她**没有"按类找一批"的入口** | 只有 `feed`（随机刷）与 `binge --search`（按作品名）；没有"某个题目/某类视频" |
| 她**没有可持久化的思路结构** | 问题/证据/结论/下一层问题只活在单次上下文；进程一重启全部消失 |
| 所以她"递归不下去" | 第二轮开始换词重复，第三轮回到标题；十次里有七次下一层问题是同一句的改写 |

结论：缺的不是提示词，是**三样结构**——固定六轴（问什么）、递归状态机（怎么往下走）、
后台执行 + 汇报（怎么真的跑完并回来说）。这三样加起来就是本轮的 `tools/brain/research/`。

## 二、结构

```
tools/brain/research/
  lenses.mjs   六轴定义：每轴 4 层（机制→边界→反例→跨轴）+ 检索词 + 伪科学判据 + 材料权重
  tree.mjs     研究树：节点/结论/证据/预算/剪枝；引用三层机械校验；原子落盘
  engine.mjs   状态机：seed → search → read → extract → cross → finalize（每步只做一件）
  notes.mjs    三种出口：自己的账（notes）/ 给他的汇报（notify）/ 进 system 的短槽（promptBlock）
tools/commands/research.mjs   CLI + 后台 worker + watchdog + 真实依赖（B站检索/debrief/LLM/QQ）
tools/lib/tools.mjs          聊天工具 research_topic（只立项，<1 秒，不阻塞聊天）
tools/bot.mjs                COMMANDS 注册
tools/lib/persona.mjs        buildMessages 注入（shadow 路径）
tools/brain/assemble.mjs     live 路径注入（与 persona 同源）
tools/lib/config.mjs         research 默认段（预算/汇报/注入字数）
test/research-test.mjs       契约测试
test/research-stress-test.mjs 高压测试
```

### 递归怎么保证（不靠模型自觉）

1. **六轴根问题不调模型**：`seedRoots` 用模板生成六个起点 —— 模型全挂也有六个明确方向。
2. **下一层问题模型优先、模板兜底**：模型给了就用；没给就按 `机制→边界→反例→跨轴` 生成。
   这样"往下走"是状态机的承诺，不是运气。
3. **剪枝**：同轴连续两支"barren"（没材料/没新结论）→ 该轴剩余支线关闭，报告里写明"为什么停"。
4. **跨轴增量**：提示词带上"其他视角已站住的结论"，并要求找这一轴特有的东西；
   完全重复的结论（相似度 > 0.72）机械拒绝。
5. **材料复用**：同一条视频可服务多个视角（不花视频预算、不重复抓取）——
   14 条视频撑起 24 个问题，否则后两层永远排不到预算。

### 防编造（三层机械闸门）

| 层 | 规则 | 挡什么 |
|---|---|---|
| ① quote | 必须是材料原文的**连续子串**（允许省略号切段 / 去标点归一化匹配） | 编造引用 |
| ② claim↔quote | 至少 1 个 2-gram 重叠 | 引用是真的、结论另编 |
| ③ claim↔(quote+context) | 至少 2 个重叠 | 完全无关的注入文本；允许抽象概括借主题词汇 |
| kind | 声称的证据类型必须在该视频材料里真实存在，否则降级 `desc` | 把热评说成字幕、用简介冒充台词 |
| 置信度 | `min(模型自评, 材料类型上限+0.15)` | 热评/简介撑不起高置信 |

### 出口

| 出口 | 内容 | 去哪 |
|---|---|---|
| notes | 六轴各最深一句 + 原话 + 交叉洞察 + 未解 + 材料清单 + 停止原因 | `~/.data/research/<id>.json` |
| 汇报 | 「扫了 N 条，有材料 M 条」+ 两轴结论 + 一条对照 + 没找到的轴 + 停因 | QQ 私聊（出站脱敏，每天 ≤3 条） |
| 注入 | ≤420 字：「我最近在琢磨的事」+ 最多四轴各一句 + 一条对照 + 还没想透 | system（只私聊；剔掉注入话术；两轴以上结论才注入） |

## 三、十遍循环（每遍：全链检查 → 高压测试 → 修缮 → 优化与增强 → 维护）

| 遍 | 全链检查（发现） | 高压测试（实测） | 修缮 | 优化与增强 |
|---|---|---|---|---|
| 1 基础正确性 | 接线四处（命令/工具/配置/双装配）；`maxTokens` 驼峰被 llm 静默忽略；门禁 3 红（未声明 `why` ×2、persona 687 行） | CLI 六种调用；真实 LLM 抽取探针：4 条结论、拒 0、2 个下一层问题、4.4s | 改 `max_tokens`；persona 抽 `researchSlot`；引擎字符串 key 改名；`setNodeStatus` 改声明 | `step` 按需 normalize（不再每步全量复制 200+ 节点） |
| 2 边界输入 | `ensureResearch` 同题/不同题语义；文件名 vs `state.id` 权威 | 空题/5000 字/怪字符/预算 0 与负值；同 id 不同题；手改 `state.id` | `idOfTopic` 用 120 字（80 字会串题）；load/update 以文件名为权威；碰撞换 id 或拒绝 | 同题已完成 → 直接返回（不重复花钱） |
| 3 证据完整性 | quote 只能挡编造引用；材料块类型未校验；拒绝原因不可观测 | 声称字幕但材料只有热评；抽象概括；无关结论；伪造引用 | 三层校验；kind 与材料实况对齐否则降级；`rejects` 按原因计数 | extract 提示词加 kind 规则；报告显示被拒数 |
| 4 递归收敛/剪枝 | 14 视频 vs 24 问题 → 后层断粮；跨轴重复；深度上限 | 复用不重复搜索；跨轴重复被拒；第三层后不再长节点 | `pickReusable`；跨轴重复机械拒绝；提示词带其他轴结论 | 读取预算检查移到复用之后（复用不花视频预算） |
| 5 并发/锁/预算 | worker 锁、watchdog、写盘失败、lease 竞态 | 两 worker 互斥；`work` 让位；watchdog dry 识别卡住 | 导出 `work`；`watchdog --dry` | persisting 失败即停（不再白烧模型/网络预算） |
| 6 故障注入/离线 | 只读目录、debrief 超时、notify 失败、生产配置 | 容器内只读 `~/.data`：`saveState` 返回 false、engine 不崩；deps 全挂；材料打包；**真机首轮六轴全 barren** | `packExcerpt` 顺序与注释一致（简介放最后）；**串片字幕丢弃**（coherence<5%）；`trusted` 标记禁止坏材料被复用 | worker 写盘失败停止；配置核对（dryRun=false、owner 已配） |
| 7 双装配路径 | persona 与 assemble 同源；群聊不注入 | 两条路径文本一致；群聊排除；只有一轴不注入 | 测试里 `updatedAt` 并列会随机命中别人（修测试数据） | `researchSlot` helper 压回行数门禁 |
| 8 安全/注入/隐私 | 材料/结论进 system 的注入面；出站脱敏 | topic 注入；脏结论注入；QQ 号；伪造引用 | `INJECTION_RE` 逐行剔除；全被剔则不注入空壳 | 群聊/陌生人隔离（与其它私事槽一致） |

## 四、终检（第 10 遍）

- 门禁：`node scripts/check.mjs` → 365 文件全绿（语法/断链/双前缀/注册/权限/catch/路径/同步异步/未声明/超时/JSON/原子写/import 方向/规模）
- 全量测试：**108 套逐套 rc=0**（新增 research / research-stress 两套）。
  验证方式（2026-11-08 补证）：`bash .tmp/verify.sh list` → `TESTS_PARSED=108`，
  再按 10 套一批跑 11 批，每套打印 `rc=`、每批 `BATCH_RESULT rc=0`、汇总 `ALL_BATCHES_FAIL=0`（脚本退出码 0）。
  为什么不用 `node tools/run-tests.mjs | tail`：管道会让退出码变成 `tail` 的，不能归因；
  而这台机器上单条长静默命令实测会在 51~73 秒被 SIGKILL（137，日志停在半截），
  分批跑同时解决"可归因"和"不被外部信号整批杀掉"两个问题。
- 门禁：`docker exec … node scripts/check.mjs > log` 无管道执行 → `GATE_EXIT=0`。
- 真实链路（容器内，真 B站 + 真模型）：首轮 0 结论（暴露串片），修复后续跑产出结论；见下节
- 注入：两条装配路径同源断言通过；群聊不注入；注入话术被剔
- 汇报：研究完成 → QQ 私聊一条（出站脱敏、每日上限）
- 续跑：watchdog 在容器重建后成功拉起 worker（log：`{"kind":"spawn","pid":48}` + `{"kind":"watchdog","out":[{"id":"…","restarted":true}]}`），
  状态从 steps=6 继续到 13+；心跳（每 5 分钟）与 entry.sh 开机各兜一层

## 五、真机实测暴露的三个结构问题（比单元测试更有价值）

真机第一轮（容器内、真 B站 + 真模型）直接失败：14 步、1 条视频、0 条结论、六轴全 `barren`。
三个原因都不是"模型不行"，而是**结构缺了一层**：

| 现象 | 证据 | 修法 |
|---|---|---|
| 字幕串片 | 标题《成瘾真相：一个视频彻底搞懂多巴胺》，字幕整段是"空镜头拍摄技巧"；模型每次都正确地判"材料无关"并 stop | `packExcerpt` 用 `subtitleCoherence < 5%` 丢弃字幕；`read` 把这类视频标 `trusted:false`，不当证据、不进复用池 |
| 坏材料被六个视角各读一遍 | 六轴 `barren` 共用了同一条串片视频（复用策略放大了错误） | `pickReusable` 只接受 `trusted !== false`，且一条视频最多服务两个视角 |
| 自我修改会杀掉研究 | 23:36 她自改 `tools/lib/tools.mjs`（加了 `bili_search` 工具）→ 23:37 容器重建 → 研究 worker 被杀，状态停在 running | ① 状态每步落盘；② watchdog 每 5 分钟由心跳拉起；③ entry.sh 开机补一次；④ 研究锁改成**心跳 TTL 锁**（pid 锁在容器重建后因 PID 复用会永久僵死）；⑤ 旧 worker 的 `touch` 失败即停手，绝不覆盖新 worker |

顺带确认：她的 `bili_search` 自改与本次 `research_topic` 在同一文件里**共存**了
（她是在我部署后的版本上改的），门禁 365 文件全绿。

## 六、明确不做

- **已完成的题不再自动重跑**：同题再立项直接返回已有结果（研究很贵，重复跑没意义）。
  想换角度就换个题目措辞（新 id），或在 QQ 里说"从 X 轴再想想"让她换题。
- **不做无材料的"研究"**：没有字幕/台词/热评/简介（≥40 字）就不抽结论，节点标 `no-material`。
- **不把热评当机制证据**：类型降级 + 置信度上限，报告里能看出每条结论来自哪种材料。
- **不做玄学**：化学/生物学轴拒绝高伪科学分数的材料（"量子疗愈/能量场"），
  哲学/精神学轴允许讨论意义与体验，但必须写成"人在这种实践里体验到什么"。
